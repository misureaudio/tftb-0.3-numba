## 3. What changed from v1 (delta)

1. **Reference tree:** tftb-0.2 → **tftb-0.3 (certified)**. All ports read `.m`/`refguide` from 0.3; all transcribed tests come from the **0.3** test files (which carry the Phase-3 C2/C3 fixes: seeded noise, justified odd-N tolerances, corrected `tfrppagt` energy assertion).
2. **Validation architecture (the core change):** v1's "transcribed tests + property tests + naive references written from tex" is replaced by a **three-layer, oracle-first** strategy (§4). The golden oracle is *value-level* (catches any deviation — index conventions, window centering, FFT normalization, odd-N behavior) where property tests are *relation-level*. Naive references are demoted to the acceleration phase's identity helper.
3. **New Phase 0 work:** the golden-data pipeline (MATLAB generator + manifest + Python ingestion), Tasks 0.5–0.7.
4. **Port template simplified:** "derive naive reference from the tex formula" → "compare against golden values" (naive reference optional, for understanding).
5. **MATLAB is one-time:** golden data is generated in batched `matlab -batch` runs (≈12 s startup each, cheap) and **committed as `.npz`**; Python CI never invokes MATLAB.
6. **Odd-N is a first-class test dimension:** the migration work proved odd N is where the bugs hide (fmtt/holdert/tfrrppat/tfrscalt all failed only at odd N). The canonical signal set includes odd-N signals and the manifest requires odd-N cases for every function.

## 4. Validation architecture (oracle-first)

### 4.1 Layers (in decreasing strength, increasing speed)

| Layer | What | Where it runs | Role |
|---|---|---|---|
| **L1 Golden oracle** | Python output vs MATLAB tftb-0.3 output on identical inputs, per (function × case), `rtol=1e-10, atol=1e-12` (per-case overrides in the manifest for functions whose own 0.3 tests use looser bounds, e.g. `fmt` odd-N `5e-2`) | pytest, pure Python | **Primary gate.** Value-level equivalence with the certified reference. |
| **L2 Transcribed 0.3 tests** | The 98 `tftb-0.3/tests/*t.m` assertion files transcribed into pytest (property-level: energy, marginals, translation covariance, unitarity, error cases), using the **fixed** 0.3 versions | pytest, pure Python | Fast regression net; encodes properties the golden cases may not cover (e.g. covariance at arbitrary shifts). |
| **L3 Property + naive** | New property tests beyond the MATLAB files; naive double-loop references (kept in `tests/reference/naive.py`) | pytest, pure Python | Safety net for golden gaps; naive refs become the **identity checker for accelerated paths** in Phase 5. |

A function is **DONE** when L1 + L2 are green for it (L3 green where applicable).

|---|---|---|

| `s_chirp` | `fmlin(256, 0.05, 0.35)` | linear chirp, ridge recovery |
| `s_parab` | `fmpar(256, [10 0.1], [128 0.25])` | parabolic IF |
| `s_sincos` | `fmsin(256, 0.1, 0.3, 64)` | sinusoidal FM |
| `s_hyp` | `fmhyp(256, [20 0.2], [200 0.05])` | hyperbolic IF |
| `s_gchirp` | `real(amgauss(256,128,60) .* fmlin(256,0.1,0.3,128))` | windowed chirp (the audit signal) |
| `s_atoms4` | `atoms(256, [30 0.1 40 1; 90 0.2 40 1; 150 0.3 40 1; 210 0.15 40 1])` | 4-component mixture, fixed coords |
| `s_pulse` | `anapulse(256, 100)` | impulse → kernel |

| `s_noise` | `rng(0); noisecg(256)` | Gaussian noise (MATLAB RNG!) |

| `s_gd` | `gdpower(256, 1, 1)` | group-delay power law |
| `s_odd` | `fmlin(131, 0.05, 0.35)` | **odd-N canonical** |

**Manifest** (`harness/golden/manifest.tsv`, the single source of truth):

```
# func    case_id  signals  args                 outputs          tol_rtol  tol_atol
tfrwv     d256     s_chirp  -                    tfr,t,f          1e-10     1e-12
tfrwv     odd      s_odd    -                    tfr,t,f          1e-10     1e-12
tfrwv     cross    s_atoms4 s_const              tfr              1e-10     1e-12
fmt       d256     s_gchirp 0.01 0.49 256        mellin,beta      1e-10     1e-12
fmt       odd      s_odd    0.01 0.49 131        mellin,beta      5e-2      5e-2   # matches 0.3 fmtt bound
...
```

Case policy: every function gets (a) a default-params case on `s_gchirp` or `s_chirp` (N=256), (b) an **odd-N case** (mandatory), (c) one non-default-params case (window/σ/K/fmin-fmax), (d) a cross-distribution case where the function supports two signals. ~100 functions × ~3.5 cases ≈ **350 golden cases**.

**MATLAB generator** (`harness/golden/`):
- `golden_signals.m` → builds the 15 signals, saves `golden/raw/signals.mat` (v7).
- `golden_eval.m` — `golden_eval(func, case_id, sig_ids, args, outs)`: evaluates the tftb-0.3 function, saves outputs to `golden/raw/<func>__<case_id>.mat` (v7). Stateless; one call per case.
- `golden_batch.m` — reads `manifest.tsv`, loops cases (each in its own `try/catch`, `clear`-safe via a stateless subfunction, exactly like the certified `run_one` pattern), prints `GOLDEN_BEGIN <func>__<case>` / `GOLDEN_OK` / `GOLDEN_FAIL <msg>` / `SUMMARY`. One `matlab -batch` invocation per phase batch.
- Precedent: the certified harness already solved the hard parts (script-`clear` isolation, `rng(0)` authority, headless shims) — `golden_batch.m` reuses `run_one.m`'s pattern verbatim.

**Python ingestion** (`tools/mat2npz.py`): converts `golden/raw/*.mat` → `golden/data/<func>__<case>.npz` (keys: `t, f, tfr, hat, ...` + `sig_*` inputs embedded, so a case file is self-contained). `.mat` intermediates gitignored; `.npz` committed. Expected repo footprint ≈ 60–150 MB (256×256 complex128 ≈ 0.5 MB; 131/221 smaller) — acceptable locally; if it grows, the fallback is per-case compression (`np.savez_compressed`).

**Python test side:**
- `tests/golden/conftest.py` — reads `manifest.tsv`, exposes fixture `golden(func, case_id)` → `dict[str, np.ndarray]` (loads the `.npz` once, caches).
- `tests/golden/test_golden.py` — **auto-parametrized** over the manifest: one test per (func, case), asserts every output var with the per-case tolerances. No per-function test code needed — adding a manifest row *is* adding a test.
- Mapping table (manifest `func` → Python callable) lives in `tests/golden/mapping.py` — the single place that knows `tfrwv → tftb.processing.cohen.WignerVilleDistribution(x, sr=1000).run()` etc.

### 4.3 Protocol

- **Generate:** `matlab -batch "addpath('D:/TOOLBOX/tftb-0.3/mfiles'); ... run golden_batch"` → `tools/mat2npz.py` → commit `golden/data/` + manifest.
- **Regenerate only** when (a) a tftb-0.3 reference change is pulled in, or (b) a golden case is found to encode a *reference bug* (document in `docs/porting-log.md`, then regenerate). Never regenerate to make a failing Python test pass — that's how oracles die.
- **MATLAB is not in CI.** The committed `.npz` files make the Python suite fully self-contained.

## 8. Risks, tradeoffs, open questions

1. **numba × numpy 2.4.6 upper bound** — Task 0.1 resolves; fallback numpy 2.3.5 is acceptable (intent = escape 1.26.4).
2. **Golden-data staleness / oracle integrity** — the failure mode is regenerating goldens to make a failing test pass. Mitigation: §4.3 protocol (regenerate only on reference change or documented reference-bug, with porting-log entry); `.npz` files are code-reviewed like code (they're committed).
3. **Reference-bug risk in tftb-0.3** — 0.3 is certified *for R2024a compatibility*, not for mathematical correctness; the migration log already found genuine 0.2 math/test defects (D1 `plotsid`→`midpoint`, D2 `tfdemo5` indexing, the false `tfrppagt` identity). If a golden case reveals a 0.3 *math* bug, the resolution is: document in `porting-log.md`, port the **correct** math (per the refguide tex), and mark that golden case `OVERRIDDEN <reason>` in the manifest (the test then compares against the documented-correct value, not the reference). This is the one sanctioned exception to "never regenerate to pass."
4. **MATLAB one-time dependency** — if R2024a is ever removed, goldens can't be regenerated. Mitigation: goldens are committed and stable; the 0.3 tree + harness remain on disk; regeneration needs only `matlab -batch`.
5. **Odd-N correctness** — first-class dimension (odd-N canonical signals + mandatory odd-N manifest case per function); the 0.3 test fixes (C2) already justify the odd-N tolerance bounds, which the manifest reuses.
6. **Repo size** (~60–150 MB of `.npz`) — acceptable locally; fallback `savez_compressed` or golden-subset-per-phase if it grows.
7. **`.mat` version** — generator saves v7 (scipy.io-compatible); h5py available for v7.3 if any case exceeds 2 GB (none expected at N≤256).
8. **Parametric family scope** (Task 4.4, 5 sub-functions) — the only Phase-4 item deferrable without breaking practical completeness; flag at review, don't silently drop.
9. **Timing** — Phase 0: ~1.5 d (golden pipeline is the new cost); Phase 1: ~2–3 d; Phase 2: ~4–6 d; Phase 3: ~2 d; Phase 4: ~4–6 d; Phase 5: ~3–4 d; Phase 6: ~0.5 d. **≈ 3–4 working weeks**; Phase 2/4 ports are independent units → parallelizable across subagents (each port = self-contained: manifest rows + code + tests + commit).
