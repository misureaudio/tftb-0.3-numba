## 4. Validation strategy (no MATLAB — per instruction)

Four independent layers, in increasing strength:

1. **Transcribed MATLAB tests.** Each of the 98 `tests/*t.m` files is read and its concrete assertions (expected values, tolerance checks, error conditions) transcribed into a pytest module `tests/reference/test_<name>.py`. These are executable specs of MATLAB behavior and the primary regression net.
2. **Property tests** (per TFR family, `tests/processing/test_properties.py`): energy conservation (`∫TFR = ‖x‖²` where the distribution is energy-preserving), time-marginal = `|x(t)|²` (Cohen class), translation covariance (shift input → TFR shifts identically), real-signal symmetry (`TFR(t,-f) = TFR(t,f)`), zero-signal → zero, cross-distribution conjugate symmetry.
3. **Naive-reference cross-checks.** For each quadratic TFR, a deliberately slow double-loop "textbook" implementation (direct from the Cohen-class kernel formula, ~20 lines, written per family in `tests/reference/naive.py`) computed on small signals (N ≤ 64) and compared with `np.allclose(rtol=1e-10)`. This catches porting errors even where the MATLAB test files are weak.
4. **Closed-form checks.** Analytic signals with known IF laws (chirps from `fmlin`/`fmpar`): ridge extraction or marginal peaks must recover the known IF law within bin resolution; `anapulse` → TFR is the kernel itself.

Tolerances: `rtol=1e-10, atol=1e-12` for naive cross-checks (same math, different order); `rtol=1e-8` for transcribed MATLAB tests (they encode MATLAB double precision).

```python
# tests/reference/naive.py — deliberately unoptimized, mathematically direct
import numpy as np

def naive_wv(x, n_fbins=None):
    """Direct Cohen-class WV: V(t,tau) = x(t+tau/2) conj(x(t-tau/2)), FFT in tau."""
    N = len(x); n = n_fbins or N
    V = np.zeros((N, N), dtype=complex)
    for t in range(N):
        for k in range(N):
            a, b = t + k, t - k
            if 0 <= a < N and 0 <= b < N:
                V[t, k] = x[a] * np.conj(x[b])
    return np.real(np.fft.fft(np.fft.ifftshift(V, axis=1), axis=1))

def naive_spectrogram(x, win):
    N, M = len(x), len(win)
    S = np.zeros((N, M), dtype=complex)
    for t in range(N):
        for k in range(M):
            a = t - k
            if 0 <= a < N:
                S[t, k] = x[a] * win[k]
    return np.abs(np.fft.fft(S, axis=1)) ** 2
```

### Phase 5 — Parallelization (Numba → CuPy), benchmark-gated

**Design principles (decided up front):**
1. **Single public API.** No `backend=` argument, no array-framework leakage. Acceleration is internal: each hot function calls a dispatcher that picks the fastest available implementation for the input size. Users never see Numba or CuPy.
2. **Benchmark gate.** A function gets an accelerated path **only if** the harness shows ≥ **3×** speedup at N = 4096 *and* ≥ **1.5×** at N = 512 (small-N overhead must not regress). Below the gate, the vectorized numpy path stays. (Rationale from prior work in this workspace: Numba gave 2.6× end-to-end where QR was the floor; CuPy was not worth it for a 57%-dense matrix on this GTX 1070 — the gate prevents repeating that.)
3. **Numerical identity.** Accelerated output must match the numpy reference within `rtol=1e-12` (same operations, reassociation only) for N ≤ 2048; `rtol=1e-10` above (FFT reassociation). A failing identity check disables the accelerated path (auto-fallback) and fails CI.
4. **Numba first, CuPy second.** Numba is CPU-only, no data transfer, and the hot loops (per-column tau loops) are embarrassingly parallel over time columns — the classic `prange` case. CuPy is only worth it for N ≥ 8192 where H2D transfer amortizes; it is an *optional extra*, not a requirement.

**Task 5.1: Numba kernels — Cohen-class tau loops**
- Create `tftb/_accel/kernels.py`. Pattern (complete example — the other kernels follow it):

```python
import numpy as np
from numba import njit, prange

@njit(cache=True, fastmath=False)
def _wv_column(signal, fwindow, t, n_fbins, tfr):
    """One time column of the pseudo-WV; called inside prange."""
    xrow = signal.shape[0]
    taumax = min(t, xrow - t - 1, n_fbins // 2, fwindow.shape[0] // 2)
    for tau in range(-taumax, taumax + 1):
        idx = (n_fbins + tau) % n_fbins
        tfr[idx, t] = fwindow[fwindow.shape[0] // 2 + tau] * \
            signal[t + tau] * np.conj(signal[t - tau])

@njit(parallel=True, cache=True)
def pwv_numba(signal, fwindow, n_fbins):
    tfr = np.zeros((n_fbins, signal.shape[0]), dtype=np.complex128)
    for t in prange(signal.shape[0]):
        _wv_column(signal, fwindow, t, n_fbins, tfr)
    return np.fft.fft(tfr, axis=0).real
```

  - Kernels to write (each = port of the existing numpy loop, one per TFR): `pwv_numba` (above), `wv_numba`, `spwv_numba` (the heaviest: 3 nested loops — the prime candidate), `spectrogram_numba`, `cohen_generic_numba(kernel, g, h)` covering Rihaczek/BornJordan/CW/GRD/ZAM/MHS/Butterworth/RID×4/Stankovic as one parameterized kernel (they share the `Στ g(τ) h(τ/ρ) x(t+τ)x*(t-τ)` skeleton — DRY), `cwt_numba` (scale loop outer, time inner — `prange` over scales).
  - `tftb/_accel/backend.py`: `get_backend(name, n)` → checks `n >= MIN_N` (from the gate), numba importable, and the identity check passed once (cached flag); returns the numba function or `None`.
  - Wire into the 0.2.0 API: e.g. `PseudoWignerVilleDistribution.run()` calls `pwv_numba(...) if (f := get_backend('pwv', N)) is not None else <existing numpy path>`. **No signature changes.**

## 7. Risks, tradeoffs, open questions

1. **numba × numpy 2.4.6 upper bound** — may force numpy 2.3.5 (Task 0.1 resolves; fallback is acceptable per the stated intent of "modern numpy").
2. **GPL license** — the MATLAB toolbox is GPL-2; the port inherits it. Fine for internal use; it constrains any commercial packaging (Task 6.3).
3. **No MATLAB oracle** — validation rests on transcribed tests + properties + naive references. Residual risk: a systematic misreading of a MATLAB file (e.g. off-by-one in a tau range, 1-indexed `H(0)`-centered window convention). Mitigation: the naive references are written *from the tex formula*, not from the `.m` code, so a shared misreading is unlikely; and the tex states the kernel explicitly.
4. **MATLAB's `H(0)-centered window` convention** — MATLAB windows are 1-indexed and centered on index `0` in the math; the 0.2.0 port already handles this in the working TFRs; each new port must reuse the exact `lh = (len-1)//2` centering idiom (and *not* reintroduce the `/ 2` float-index bug class we fixed in `PseudoPageRepresentation`).
5. **CuPy on GTX 1070 (sm_61)** — supported by cupy-cuda12x 14.2.0, but 8 GB VRAM and Pascal-era compute cap mean the gate will likely reject most CuPy paths; that is an acceptable, documented outcome, not a failure.
6. **Scope creep in parametric family** (Task 4.4, 5 sub-functions) — if it proves disproportionately hard, it is the only phase-4 item that can be deferred without breaking the "complete port" claim's usefulness; flag at review, do not silently drop.
7. **Timing estimate** — Phase 0: ~0.5 d; Phase 1: ~2–3 d (9 fixes + numpy sweep); Phase 2: ~4–6 d (11 ports × template); Phase 3: ~2 d; Phase 4: ~4–6 d (CWT + Mellin + Zak + parametric + utilities); Phase 5: ~3–4 d (incl. benchmarking); Phase 6: ~0.5 d. **Total ≈ 3–4 working weeks** at one implementer, parallelizable across subagents by phase-2/4 function granularity (each TFR port is an independent unit).
