## 2. Design

### 2.1 New module (the only new file)

`tftb/_accel/cupy_kernels.py` — self-contained, exposing exactly:

```python
cwt_cupy(signal, fmin=0.01, fmax=0.5, n_voices=None, wave=2)
spwv_cupy(signal, ...)                 # same signature as cohen.smoothed_pseudo_wigner_ville
spectrogram_cupy(signal, ...)          # same signature as Spectrogram().run() (returns the same tuple)
```

- **Lazy CuPy import**: the module imports cleanly without CuPy; each function
  raises a clear `ImportError` ("install the `cupy` extra") when called without
  it. CuPy remains an optional extra — never a hard dependency.
- **Guards, per user constraints** (each raises a clear error, no silent
  fallback to numpy/numba — an explicit CuPy call must run on CuPy or fail
  loudly):
  - signal length **N ≥ 8192** (inclusive);
  - CUDA device present (`cupy.cuda.runtime.getDeviceCount() > 0`).
- **Returns numpy** arrays (`.get()`), same tuples/dtypes as the standard API.
- **Zero changes** to `kernels.py`, `backend.py`, or the existing `cwt` /
  `spwv` / `Spectrogram` dispatch — the Numba implementation stays untouched.
  The Numba path remains the default for everything; 5.3bis only *adds* three
  functions.

### 2.2 Implementation notes

- `spectrogram_cupy`: batched FFT of the windowed frames
  (`cupyx.scipy.fft.fft` over a (N, nts) matrix, axis 0) — the direct
  CuPy-friendly form of `Spectrogram.run`.
- `spwv_cupy`: same batched-FFT structure as the numpy `tfrspwv`
  (pre-FFT matrix → one batched FFT → real). Note: this attacks the FFT step,
  not the tau loop — see §4.
- `cwt_cupy`: per-voice FFT-based convolution via batched transforms
  (wavelets are precomputed on the numpy side, as in the Numba design).
- Identity: compare each `*_cupy` against the corresponding standard function
  (rtol 1e-10 for N > 8192, per the plan's identity rule for large N).

## 3. Functions in scope (3)

| function | current best path (post 5.1/5.2) | CuPy branch competes against |
|---|---|---|
| `cwt` | numpy-only (documented FFT-bound) | numpy |
| `spwv` | **Numba** (33.8× @2048, 32.9× @4096 vs numpy) | the Numba kernel |
| `spectrogram` | numpy-only (documented FFT-bound) | numpy |

## 4. Candidate analysis (measured on this machine)

Environment verified 2026-10-08: **GTX 1070 (8 GB), CuPy 14.2.0**,
`cupyx.scipy.fft` batched transforms work. Measured:

- 1-D FFT 8192: 0.107 s (first call, includes init)
- batched FFT (8192, 512) axis 0: 1.145 s (first call)
- batched FFT (8192, 8192) axis 0: 0.214 s (warm)
- D2H 8192×512 complex: 0.040 s

Per-function expectations (to be confirmed by the gate, not assumed):

- **`spectrogram` — strongest candidate.** Pure batched FFT; numpy baseline
  6.98 s @8192 (×3 reps). A (8192, 8192)-class batched FFT is ~0.2 s warm on
  this card, so a large win is plausible at N > 8192.
- **`cwt` — weak candidate.** numpy is already 0.062 s @8192 (cheapest
  function in the suite); the per-voice FFT-conv may not beat it, and the
  gate may legitimately say no.
- **`spwv` — weak candidate.** The cost is the O(N·Lg) tau loop, which the
  Numba kernel already accelerates 33× (≈11 s extrapolated @8192 vs the 365 s
  numpy baseline). A batched-FFT CuPy version does not touch that loop, so it
  competes against ~11 s of Numba time with an FFT-only strategy.

**Explicitly allowed outcome (unchanged from the plan):** "CuPy not worth it
on this GTX 1070" — recorded with numbers, per the DynamicSystems precedent on
this same card (CuPy ruled out there for a 57%-dense convective matrix).

## 5. Gate review & recording

- Same rules as 5.1/5.2: identity vs the current path (rtol), speedup table,
  gate ≥3× (the plan's ≥1.5× @512 sub-gate does not apply — 5.3bis is N ≥ 8192
  only).
- Results → `docs/benchmarks.md` ("Phase 5.3 — CuPy (explicit API)") and a
  Task 5.3bis entry in `docs/porting-log.md`.
- A function that fails the gate is simply *not advertised*: its `*_cupy`
  stays available (it is an explicit opt-in), and the benchmark table records
  the measured ratio. No demotion machinery needed — there is no default path
  to demote from.

## 6. Tests

`tftb/tests/benchmarks/test_cupy.py`:

- skipped (not failed) when CuPy is absent or no device;
- identity of each `*_cupy` vs the standard function at N = 8192 (the gate
  size) — slow, marked `slow`;
- guard tests: N = 4096 (< 8192) raises; missing CuPy raises
  `ImportError` (mocked); no silent fallback (a raised CuPy error propagates).
